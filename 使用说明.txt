秋招投递管理网页｜使用说明

1. 双击打开“index.html”。
2. 建议固定使用同一个浏览器打开。新增、编辑、删除和行内修改后，数据都会自动保存在该浏览器本地。投递列表会按“进行中 / 已 OC / 已结束”分区，每个分区内再区分互联网、央国企和待分类公司；不同阶段使用不同背景色。
3. 默认不上传数据；只有配置飞书并手动点击同步时，结构化文字记录才会发送到你的 Worker 和飞书，截图不会上传。
4. 清理浏览器网站数据、换浏览器或换电脑后，本地记录不会自动带过去。请定期通过“工具”→“导出 JSON”备份。
5. “工具”→“导出 JSON”会下载一个名称带当天日期的备份文件，不会修改网页中的现有记录。
6. 安装“秋招一键收录”插件后，可以点击“工具”→“识别投递网址”，粘贴详情页地址，自动识别公司、岗位、投递日期、状态、城市和原网址，再确认保存。
7. 点击“截图识别”后，可复制截图并直接按 Command + V 粘贴，也可以一次选择或拖入最多 20 张岗位详情页/投递页面截图。网页会先增强图片清晰度再在本地识别，公司、岗位、城市和投递日期可先修改或取消勾选，再批量加入岗位库；相同公司和岗位会自动合并。截图不会上传，未明确识别到的日期会保持空白。
8. 截图识别依赖同目录中的“ocr”文件夹。外发或移动时，必须把 index.html 和 ocr 文件夹放在一起，不要只发送 index.html。
9. 点击“数据安全”可以设置电脑本地自动备份文件。设置完成后，新增、编辑、删除和行内修改都会同步生成浏览器快照，并尝试更新备份文件。
10. “导入备份文件”可以恢复此前导出的 JSON；导入或恢复快照前，网页还会自动下载一份当前数据，避免误覆盖。
11. 顶部“岗位库”标签页可以通过新版一键收录插件同步指定的腾讯招聘文档，并支持搜索、打开岗位和“记为已投递”。岗位库使用独立本地存储，不会覆盖正式投递记录。
12. 当前 GitHub Pages 地址需要插件 1.5.0 或更高版本。重新解压新版插件后，请在扩展程序页面点击“重新加载”，然后刷新管理器网页。
13. 飞书同步需要先部署 worker 文件夹中的 Cloudflare Worker，并在“工具”→“飞书同步设置”中填写 Worker 地址、同步令牌和空白多维表格链接。同步为单向新增/更新，不会删除飞书记录。
14. 手机 App：请用手机打开 GitHub Pages 的 https 网页。iPhone 用 Safari 点击“分享”→“添加到主屏幕”；Android 用 Chrome 点击网页里的“安装到手机”，或菜单里的“安装应用/添加到主屏幕”。本地 file:// 文件不能安装成手机 App。
15. 更新 GitHub 网页后，手机 App 会自动读取新版本；投递记录仍保存在当前手机浏览器本地，不会被网页代码覆盖。电脑与手机数据不会自动同步，首次换设备请在旧设备“导出 JSON”，再在新设备“数据安全”中导入 JSON 备份。
16. 发布 GitHub Pages 时，仓库根目录必须同时包含 index.html、manifest.webmanifest、service-worker.js、icons 和 ocr 文件夹，不要只上传 index.html。

文件夹中的网页可以移动，但移动后部分浏览器可能会把它视为新的本地页面。为避免找不到旧记录，建议确定存放位置后不要再移动。

重要：更新网站功能时必须保留存储标识 autumnRecruitmentTracker.records.v1，并继续通过兼容迁移读取旧字段。替换网页前建议先点击“立即同步备份”。
